# 2026-06-09_v4.md — Revision Plan for `qa_summary.py`

## Goal

Revise `qa_summary.py` so the QA summary generation is **arm-specific** and **design-file-driven**.

The script must read the two study-design Excel files:

```text
Required_Sessions_for_each_Arm.xlsx
Instruments_in_each_Session_each_Arm.xlsx
```

These files should define the required sessions and required instruments for each arm. The final subject-level output should include **only required sessions and required instruments** for each subject's arm.

The script should generate separate output files by arm:

```text
QA_summary_arm1.xlsx
QA_summary_arm2.xlsx
QA_summary_arm3.xlsx
```

Each output workbook should contain:

```text
subject_wise
group_wise
```

## Arm assignment logic

### 2. Infer arm from `subject_id`

Add a helper function that determines arm from the last three digits of `subject_id`.

Rule:

```text
last-three digits starting with 1 -> arm1
last-three digits starting with 2 -> arm2
last-three digits starting with 3 -> arm3
```

Examples:

```text
101     -> arm1
205     -> arm2
312     -> arm3
sub-101 -> arm1
sub-205 -> arm2
sub-312 -> arm3
```

Recommended helper:

```python
def infer_arm_from_subject_id(subject_id: str) -> str:
    digits = ''.join(ch for ch in str(subject_id) if ch.isdigit())
    if len(digits) < 3:
        return 'unknown'

    arm_digit = digits[-3]
    if arm_digit == '1':
        return 'arm1'
    if arm_digit == '2':
        return 'arm2'
    if arm_digit == '3':
        return 'arm3'
    return 'unknown'
```

Every subject in the final outputs must have one valid arm:

```text
arm1
arm2
arm3
```

Subjects with unknown arm assignment should be logged and excluded from arm-specific outputs unless an explicit debug option is enabled.

## Required-only subject-level output

### 5. Make `subject_wise` protocol-driven

For each subject:

1. Standardize `subject_id`.
2. Infer `arm` from subject ID.
3. Select required sessions for that arm from `required_sessions_by_arm`.
4. Select required instruments for each required session from `required_instruments_by_arm_session`.
5. Generate subject-level columns only for those required sessions and instruments.
6. Fill observed REDCap/MRI QC values when present.
7. Mark required-but-missing records as `missing`.
8. Do not create columns for non-required sessions or non-required instruments.

This applies to:

- questionnaire date/status columns
- task completion columns
- behavioral QC columns
- MRI QC columns, when MRI expectedness is defined in the design files
- session timing columns
- subject-level completeness/readiness summary columns

### 6. Do not write unexpected records into standard columns

If an observed REDCap or MRI QC record exists but the arm/session/instrument is not required by the design files:

- do not create a standard `subject_wise` column for it
- log it as an unexpected observation
- optionally write it to a debug sheet only if a debug option is enabled

Recommended validation-log category:

```text
unexpected_observed_records_not_required_by_design
```

## Group-wise output updates

### 8. Make `group_wise` arm-specific and expectedness-based

Each arm-specific `group_wise` sheet should summarize only:

- subjects assigned to that arm
- sessions required for that arm
- instruments required for that arm/session

All denominators should be expected records from the design files, not observed records.

Use expected denominators such as:

```text
expected_NofSubjects
expected_NofRecords
```

Rates should be calculated as:

```text
complete_rate = complete_NofSubjects / expected_NofSubjects
missing_rate = missing_NofSubjects / expected_NofSubjects
qc_pass_rate = qc_pass_NofSubjects / expected_NofSubjects
```

Do not include `not_expected` records in denominators.

### 9. Keep the seven-table `group_wise` layout

Each arm workbook should keep the expected seven separate tables:

1. Questionnaire completion and missingness by session
2. Instrument-wise summary
3. Task completion by session
4. Behavioral QC pass rate by session
5. MRI QC pass rate by session
6. Session interval summary after Baseline
7. Participant-level QA readiness summary

Each table should include an `arm` column.

Rows should be ordered by session order, then instrument/task/scan name, then source where applicable.

Do not sort sessions alphabetically.

## MRI QC integration reminder

### 10. Keep MRI QC from external QC CSVs

Do not read MRI QC flags from REDCap fields.

MRI QC should come from:

```text
QC_anat.csv
QC_func.csv
```

Use `Poor_Quality` as the QC flag:

```text
Poor_Quality == True  -> qc_status = fail, qc_pass = False
Poor_Quality == False -> qc_status = pass, qc_pass = True
```

If MRI expectedness is defined in `Instruments_in_each_Session_each_Arm.xlsx`, use the design file as the denominator source.

If MRI expectedness is not defined there, include observed MRI QC rows by arm and clearly log that MRI expectedness was observation-based.

Important MRI session mapping:

```text
ses-T6  -> T6 Scan
ses-T12 -> T12 Scan
```

Do not mix MRI scan sessions with treatment sessions `T6` and `T12`.
