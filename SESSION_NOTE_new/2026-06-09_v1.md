# Required revisions

## 1. Remove `source_group` from `subject_wise`

### Current issue

The current `subject_wise` output includes a `source_group` column that records whether the subject appears in `ParticipantsQAtracker.csv`, `ClinicianQAtracker.csv`, or both.

This is no longer needed.

### Required behavior

`subject_id` should be the only subject-level merge key.

If the same `subject_id` appears in both CSV files, records from both CSV files should be treated as records for the same subject and combined into one row in `subject_wise`.

Do not include this column in the final Excel output:

```text
source_group
```

### Internal tracking

It is still okay to keep these fields internally in long-format tables:

```text
source_file
instrument_source
```

These should be used only for debugging, duplicate detection, and preventing column overwriting.

They should not become subject-level summary columns.

### Code change

In `pivot_long_tables_to_subject_wise()`, remove logic like:

```python
source_group = ",".join(sorted(df_subject["source_file"].unique()))

out = {
    "subject_id": subject_id,
    "source_group": source_group,
    "dropout_status": ...,
}
```

Replace with:

```python
out = {
    "subject_id": subject_id,
    "dropout_status": ...,
}
```

## 2. Merge subjects across CSVs, but prevent instrument-level column overwriting

### Current issue

If the same subject has records in both CSV files, the current wide pivot can overwrite columns when the same questionnaire/task/scan name appears in both files.

For example, both files may generate:

```text
ses-Baseline_qn-VisitStatus_status
```

One value could overwrite the other.

### Required behavior

Subjects should be merged by `subject_id`, but instruments that appear in both CSV files must have distinct output names.

### Recommended approach

Add an internal standardized field:

```text
instrument_source
```

Use values like:

```text
participants
clinician
```

Then add output-name fields before pivoting:

```text
questionnaire_output_name
scan_or_run_output_name
task_output_name
```

### Naming rule

If a questionnaire/task/scan appears in only one source file, use the clean instrument name directly.

Example:

```text
ses-Baseline_qn-PHQ9_status
```

If the same `session + questionnaire` appears in both source files, prefix the instrument name with the source:

```text
ses-Baseline_qn-participants_VisitStatus_status
ses-Baseline_qn-clinician_VisitStatus_status
```

Apply the same rule for MRI QC and behavioral QC:

```text
ses-T6Scan_mri-participants_SelfOtherRun1_qc_status
ses-T6Scan_mri-clinician_SelfOtherRun1_qc_status

ses-T6_beh-participants_SelfOther_qc_pass
ses-T6_beh-clinician_SelfOther_qc_pass
```

### Suggested helper functions

Add:

```python
def add_questionnaire_output_names(qlong: pd.DataFrame) -> pd.DataFrame:
    """
    Add questionnaire_output_name.
    Prefix questionnaire with source_file only when the same
    session + questionnaire appears in more than one source_file.
    """
```

Add:

```python
def add_qc_output_names(qc_long: pd.DataFrame, item_column: str, output_column: str) -> pd.DataFrame:
    """
    Add scan_or_run_output_name or task_output_name.

    """
```

Use these output-name columns in `pivot_long_tables_to_subject_wise()`.

## 5. Rewrite `group_wise` as five separate tables, not one mixed table

### Current issue

The current `build_group_wise()` concatenates many different summaries into one dataframe with many columns.

This creates one large mixed table where many columns are irrelevant for many rows.

### Required behavior

The Excel sheet `group_wise` should contain five separate tables on the same sheet.

Each table should have:

1. a clear title row
2. its own header row
3. its own table-specific columns
4. blank rows between tables

Do not concatenate all group-wise summaries into one dataframe.

def write_group_wise_tables(writer, group_tables: dict[str, pd.DataFrame]) -> None:
    sheet_name = "group_wise"
    startrow = 0

    for table_title, table_df in group_tables.items():
        pd.DataFrame([[table_title]]).to_excel(
            writer,
            sheet_name=sheet_name,

# Validation updates

Update validation checks to include:

```text
- No source_group column in subject_wise.
- One row per unique subject_id.
- Subjects appearing in both CSV files are merged into one row.
- Instruments duplicated across CSV files are renamed with source-specific prefixes.
- No final session values contain REDCap unique event names.
- No final column names contain `_arm_`.
- No final output values contain `UNMAPPED_EVENT_` unless debugging is explicitly allowed.
- No Screening interval columns.
- No Baseline intervalFromBaseline columns.
- group_wise contains five separate tables with table titles.
```

Suggested validation helper:

```python
def validate_final_output(subject_wise: pd.DataFrame, group_tables: dict[str, pd.DataFrame], log: ValidationLog) -> None:
    if "source_group" in subject_wise.columns:
        raise ValueError("source_group should not appear in subject_wise output.")

    duplicated_subjects = subject_wise["subject_id"].duplicated().sum()
    if duplicated_subjects:
        raise ValueError(f"subject_wise has duplicated subject_id rows: {duplicated_subjects}")

    bad_columns = [col for col in subject_wise.columns if "_arm_" in col.lower()]
    if bad_columns:
        raise ValueError(f"Final subject_wise columns contain REDCap unique event names: {bad_columns}")

    baseline_interval_cols = [
        col for col in subject_wise.columns
        if "ses-Baseline" in col and "intervalFromBaseline" in col
    ]
    if baseline_interval_cols:
        raise ValueError(f"Baseline interval columns should not exist: {baseline_interval_cols}")

    screening_interval_cols = [
        col for col in subject_wise.columns
        if "ses-Screening" in col and "intervalFromBaseline" in col
    ]
    if screening_interval_cols:
        raise ValueError(f"Screening interval columns should not exist: {screening_interval_cols}")

    expected_tables = 5
    if len(group_tables) != expected_tables:
        raise ValueError(f"Expected {expected_tables} group-wise tables, found {len(group_tables)}")
```
