# 2026-06-09 v6 Revision Plan for `qa_summary.py`

## Goal

Correct the calculation of `complete_all_experiment_sessions`.

Current problem: `complete_all_experiment_sessions` is calculated from `session_long` rows where `interval_valid != "not_expected"`. This means the flag is driven by whether a session has timing-window rules, not by whether the session is required for the subject's arm. If a required session has no interval/timing rule, it can be excluded from the completeness check. This is not correct.

Expected behavior: `complete_all_experiment_sessions` should mean:

> For each subject, all sessions required for that subject's arm in `Required_Sessions_for_each_Arm.xlsx` are completed.

The subject's arm is determined from `subject_id`: the last-three-digit rule already implemented in the script should continue to be used:

- last-three digits starting with `1` -> `arm1`
- last-three digits starting with `2` -> `arm2`
- last-three digits starting with `3` -> `arm3`

`Screening` should remain excluded from output and from this required-session completeness flag.

---

This treats `interval_valid != "not_expected"` as the definition of required experiment sessions. That is wrong because `interval_valid` is about timing-window evaluation, not session expectedness.

## Expected behavior after revision

For each subject:

- Determine the subject's arm from `subject_id`.
- Look up required sessions for that arm from `Required_Sessions_for_each_Arm.xlsx`.
- Exclude `Screening`.
- Check whether every required session has `session_completed == True` in `session_long`.
- Set `complete_all_experiment_sessions = True` only when all required sessions are completed.
- If one or more required sessions are missing, set:
  - `complete_all_experiment_sessions = False`
  - `missing_required_experiment_sessions` to a semicolon-separated list of the missing sessions
  - `needs_followup = True`
  - `ready_for_analysis = False`

## Key distinction to preserve

Do not merge these two concepts:

### Required-session completion

Question:

> Did the subject complete every required experiment session for their arm?

Source:

```python
Required_Sessions_for_each_Arm.xlsx
```

Output:

```python
complete_all_experiment_sessions
missing_required_experiment_sessions
```

### Session interval validity

Question:

> For sessions with timing-window rules, are the dates within the allowed range from baseline?

Source:

```python
CONFIG["session_timing_windows"]
```

Output:

```python
ses-<Session>_interval_valid
all_required_criteria_passed
ready_for_analysis
needs_followup
```

These are related QA concepts, but they are not the same denominator and should not be calculated from the same filter.

## Regression test examples

### Case 1: required session has no timing-window rule

- Arm design requires: `Baseline`, `T1`, `T2`.
- `CONFIG["session_timing_windows"]` only defines `T1`.
- Subject has completed `Baseline` and `T1`, but not `T2`.

Expected:

```python
complete_all_experiment_sessions == False

needs_followup == True
ready_for_analysis == False
```

- Arm design requires: `Baseline`, `T1`, `T2`.
- Subject has non-empty session dates for all three.

Expected:

```python
complete_all_experiment_sessions == True
missing_required_experiment_sessions == ""
```

### Case 3: unknown arm or missing design rows

- Subject arm cannot be inferred, or no required sessions are defined for the inferred arm.

Expected:

```python
complete_all_experiment_sessions == False
ready_for_analysis == False
```

Also confirm this condition is visible in the validation log.
