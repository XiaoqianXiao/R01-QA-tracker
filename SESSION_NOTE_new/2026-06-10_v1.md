## Change 2. Standardize `subject_id` to the three-digit study ID

The standardized `subject_id` should be a three-digit string such as:

```text
101
205
312
```

Rules:

### REDCap QA exports

For REDCap files:

```text
ParticipantsQAtracker.csv: record_id     = 101 -> subject_id = 101
ClinicianQAtracker.csv:    preescreen_id = 205 -> subject_id = 205
```

The subject ID value should already be the study ID. Still, normalize it defensively by stripping whitespace and keeping the three study-ID digits.

### MRI QC files

For MRI QC files:

```text
QC_anat.csv/QC_func.csv: subID = sub-312 -> subject_id = 312
```

Rules:

- `subID` is expected to have prefix `sub-`.
- Remove the `sub-` prefix.
- Keep the three digits after `sub-`.
- If the value has extra text, extract digits and use the last three digits only if this matches existing project conventions.
- Log any non-standard `subID` values.

Recommended implementation:

```python
def standardize_subject_id(raw_value: str, source_file: str) -> str:
    raw = str(raw_value).strip()

    if source_file in {"QC_anat.csv", "QC_func.csv"}:
        if raw.startswith("sub-"):
            raw = raw[4:]
        else:
            log_warning(f"MRI QC subID does not start with sub-: {raw}")

    digits = "".join(ch for ch in raw if ch.isdigit())

    if len(digits) >= 3:
        return digits[-3:]

    return digits
```

Important:

- Use the standardized `subject_id` everywhere downstream.
- The final `subject_wise` sheet should use standardized IDs such as `101`, not `sub-101`.
- MRI QC records with `sub-101` must merge with REDCap records with `101`.

## Change 3. Infer arm from the first digit of standardized `subject_id`

After standardization, infer arm using the first digit of the three-digit `subject_id`:

```text
subject_id first digit == 1 -> arm1
subject_id first digit == 2 -> arm2
subject_id first digit == 3 -> arm3
```

Recommended implementation:

```python
def infer_arm_from_subject_id(subject_id: str) -> str:
    sid = str(subject_id).strip()

    if len(sid) < 3:
        return "unknown"

    arm_digit = sid[0]

    if arm_digit == "1":
        return "arm1"
    if arm_digit == "2":
        return "arm2"
    if arm_digit == "3":
        return "arm3"

    return "unknown"
```

Implementation requirements:

- Run `infer_arm_from_subject_id()` only after `standardize_subject_id()`.
- Do not infer arm from the original `subID` string, such as `sub-312`.
- Do not infer arm from the first digit of all digits before standardizing.
- Subjects with unknown arms should be logged and excluded from arm-specific output unless a debug option explicitly keeps them.

## Change 6. Split session interval logic from `complete_all_experiment_sessions`

The updated `PROJECT_CONTEXT.md` separates these into two independent rules:

```text
### 9. Session interval rule
### 10. `complete_all_experiment_sessions` rule
```

Update `qa_summary.py` to reflect this separation.

### 6A. Session interval rule

Session interval logic should only support timing/window summaries.

Rules:

- Calculate intervals from Baseline only for required sessions after Baseline.
- Do not create interval columns for `Screening` or `Baseline`.
- Do create interval columns only for required post-baseline sessions for the subject's arm.
- Do not use interval validity to decide whether all experiment sessions are complete.

Final output should not contain:

```text
ses-Screening_intervalFromBaseline_weeks
ses-Baseline_intervalFromBaseline_weeks
```

### 6B. `complete_all_experiment_sessions` rule

`complete_all_experiment_sessions` must be calculated from the required session design, not from interval-window rules.

Correct source:

```text
Required_Sessions_for_each_Arm.xlsx
```

Correct logic:

```python
required_sessions = get_required_sessions_for_arm(subject_arm)
required_sessions = [s for s in required_sessions if s != "Screening"]

complete_all_experiment_sessions = all(
    session_completed(subject_id, session)
    for session in required_sessions
)
```

Do not calculate it from:

```python
session_long[session_long["interval_valid"] != "not_expected"]
```

Reason:

```text
Sessions without timing-window rules could be wrongly excluded from all-session completion checks.
```

Implementation requirements:

- Create or update a helper such as `compute_complete_all_experiment_sessions()`.
- The helper should receive the required session list from the design file.
- The helper should not depend on `interval_valid`.
- The helper should return both:

```text
complete_all_experiment_sessions
missing_required_experiment_sessions
```

Recommended helper interface:

```python
def compute_complete_all_experiment_sessions(
    subject_id: str,
    arm: str,
    required_sessions_by_arm: pd.DataFrame,
    session_completion_lookup: dict,
    excluded_sessions: set[str] = {"Screening"},
) -> tuple[bool, str]:
    ...
```
